# Independent first rendered pass — visual review

4 November 2026. Compared actual root captures in TEMP/website-build/captures (home phone/desktop, docs phone, article desktop) with these selected hybrid boards. These are the first rendered captures; root reports subsequent hero aspect-ratio and actor-position corrections, so those old differences are excluded from the recommendations below. No browser, application source or service operation was performed by this reviewer.

## What is working

The implementation clearly carries the approved teal/ivory/apricot identity. Actual owned environment artwork is bright and substantial, the canonical actor is present, primary app entry is conspicuous, and documentation has a quiet readable article surface. The desktop reading column and grouped guide navigation are practical. The narrow phone version reflows rather than shrinking a desktop view. No major redesign is suggested.

## Actionable refinements

1. **Restore the inner preview-window cue.** In the first home capture, the art floats above a muted “Home & garden” caption. A narrow teal title bar and crisp border around the scene would more strongly carry Little Life Utility's selected layout, without fake minimize/close controls. Keep the full scene contained with padding.
2. **Remove duplicate network metadata on phone.** The tiny two-line worlds/Testnet text in the title bar plus another hero network line repeat the same information. Prefer one compact Testnet badge or label and use the space for the scene and action. The app remains responsible for actual world selection.
3. **Identify the NFT in the first viewport.** The first home screen calls this an AI-led life game but does not yet say NFT. A concise eyebrow such as “An AI-led NFT life game” adds the ownership premise without a paragraph or finance panel.
4. **Keep the actual rooster visible at phone scale.** A slightly larger nearest-neighbor presentation of the canonical sprite could make the life easier to notice against the garden. Preserve the original pixels/identity and use its existing animation; do not redraw it.
5. **Tighten the phone handbook's introduction.** The heading, description, search and first-day card are clear but consume much of the first viewport. Slightly reduce their vertical gaps so the first practical topic group is easier to reach. More promotional illustration or copy is unnecessary.

The real selected UI should use ordinary, direct language. The generated boards are a placement/art guide and include copy artifacts already recorded in NOTES.md; do not copy their “your choices” wording or artificial window-control affordances.

These findings concern presentation, not route correctness, fee handling, wallet behavior, search implementation or chain verification. Root owns those separate checks.
