# Website exploration — PM review

4 November 2026. The PM inspected every selected homepage, game explanation and guide. A separate reviewer inspected all 18 actual images against current game facts. This is an owner-choice design review, not verification of a built website.

## Outcome

The six sets express different useful identities and each covers a public-site idea beyond its hero. Keep all six for selection. Homepage and guide can come from different sets; typography, layout and motion should then be reconciled deliberately.

## Carry forward after selection

Use the actual rooster generator and owned game captures/assets. Generated environments are composition studies, not replacement maps, furniture, plants or inventory. Replace packed watering cans with the bottle; a well watering tool may remain environmental scenery. Use the actual supported flower/fruit/tree catalog. The archive phone's “Save first, then watch” should read “The day is saved, then its film plays” so it does not imply a separate manual Save action.

Make text real HTML rather than a hero bitmap. Check real 320/390/430 phone widths, enlarged text, touch targets and guide contents. Do not shrink an entire desktop stage to fit. Small motion should bring light, foliage, windows or parcels alive without a compulsory video, example film or game-engine download before Open App and docs.

Future routing must preserve exact world/collection/token links, returning-life context and interrupted-wallet recovery. The website must not create another wallet connection or reset the app. Wallet/world/deployment facts must match current testnet configurations; distinguish free sign-in from paid acceptance.
