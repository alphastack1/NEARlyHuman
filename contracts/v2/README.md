# Authoritative V2 testnet candidate

This candidate is separate from the deployed V1 collection. It contains no free-founder helper, fixture token issuer, supplied final-state blob or supplied death flag. Native NFT purchase is separate from signed paid-day admission. It has not been deployed publicly by the foundation wave.

- `V2ActionModule` executes typed legal actions over an owned snapshot, including one inventory shared by garden, workshop and household uses. It also exposes the common deterministic draw primitive.
- `V2LifeVerifier` owns the sixty-slot clock, condition deadlines/tombstones, incident admission, bounded hypothetical care certificates, growth, terminal prefixes and output-point derivation. Its action module is immutable. Certificate failure is caught through a gas-bounded self-staticcall and softens the proposed onset; hypothetical state never becomes the actual save.
- `NEARlyHumanV2` owns ERC-721 identity, signed admission, accepted state/revision/request, reserved reward capacity, backed purses, withdrawal, native purchase and token-funded births. The verifier is immutable. The constructor permits only chain46630 or local31337.
- `NEARlyHumanCoin` has six decimals and controlled vault mint/burn. Only verified shipment credit can mint units through the controller. Wallet/purse births burn250; lifetime issuance does not decrease.

Deploy action module, then verifier(action module), then controller(verifier, relayer, quote signer, treasury, native testnet mint price). The controller deploys its own token. Every module must remain below the24,576-byte runtime limit; compilation uses solc0.8.38, via-IR, optimizer1 and Cancun.

`acceptDay(Admission,signature)` uses EIP-712 domain name `NEARlyHuman V2`, version `2`, actual chain and controller. The admission fields and order match `src/chain/v2-admission.ts`. Signature authorizes player, NFT, accepted revision, care kit, shipping mode, native processing fee, configured multiplier, expiry and decision configuration. No inference should begin before the hosted worker independently verifies the actual accepted transaction and its durable budget reservation.

`finalize(id,trace,certificate,replayCommitment)` takes typed action/certificate bytes and a nonzero rich-packet commitment. Biology/material results and shipment points come from the immutable verifier. The commitment binds the already-stored film/choice packet but is never biological authority. `DayRecord.history` stores one goal byte plus eight bytes per action; `traceHash` remains the hash of the reconstructed ABI trace. `src/v2/history.ts` provides the matching compact codec.

Subsequent targeted runs verified compact history, valid multi-day care certificates, the root-owned admission digest helper and the nonzero replay commitment. These are cumulative scoped captures, not a claim that every capture used the final metadata/storage layout.
